# Stage B：Ascend NPU 与 MiniCPM-o Base 准备计划

## 目标

在不影响现有云端任务、不下载模型到个人电脑、不上传私有资料的前提下，
完成 MiniCPM-o 4.5 Base 基线所需的环境探针、离线输入契约、十条合成
多模态 smoke 样本和可复现实验记录入口。

本计划不宣称 Base 推理、LoRA、RAGSDK 昇腾链路或全双工语音已经完成。
这些能力只有在云端产生可复现日志和冻结评测结果后才可对外陈述。

## 2026-07-29 完成记录

本计划中的环境探针、模型固定版本缓存、Base 四路线 smoke、冻结评测、
LoRA 单步训练、适配器重载、同集复评、晋级比较和发布扫描均已完成。
Base 与 LoRA 的 10 条多模态 smoke 均通过；冻结合成集复合分数均为
0.1333，结论为 `retain_base`。完整、不过度推断的结果见
`docs/stage-b-npu-results-2026-07-29.md`。

## 已确认边界

- 个人电脑不下载 MiniCPM-o 权重。
- 模型以后只由云端直接写入云端持久化缓存。
- 私有语料、本地索引、本地 Qwen、个人材料和历史输出不得进入云端。
- 当前开发环境已重新启用；模型只能由云端直接缓存，重新连接后先核验后台
  下载状态和精确 revision，再加载模型。
- Stage A 合成发布包是唯一候选数据输入；只允许上传通过安全门禁的公开包。
- 源码仓库不提交模型、数据包、检查点、实验输出或环境凭证。

## 当前只读环境事实

2026-07-29 从 HiDevLab 资源页和最小运行探针确认：

- 资源页标识 Atlas 800T A3 训练服务器、1 个 NPU 配额、40 vCPU、
  240 GiB、300 GB 存储，Ubuntu 22.04、Python 3.11；
- 运行环境为 Python 3.11.15、PyTorch 2.10.0、torch-npu 2.10.0；
- `torch.npu.is_available()` 为真，运行时可见两个逻辑设备；
- `npu-smi 25.5.1` 对芯片返回通用 `Ascend910`，每个逻辑设备显示
  65536 MB HBM；
- 2×2 NPU 矩阵乘法已成功。

资源页的“1 个 NPU”与运行时“两个逻辑设备”属于分配与芯片拓扑的不同
视角，不据此声称拥有两张物理卡。上述信息也不等于 MiniCPM-o 已兼容。
官方 MiniCPM-o 4.5 Transformers 示例使用 `trust_remote_code` 和 BF16；
仍需验证模型加载、视觉、音频与训练算子。

## 实施顺序

### B0：本地准备

1. 增加只读环境探针，不输出用户名、主机名、环境变量、路径或设备序列号。
2. 增加模型缓存与 Stage A 发布包的离线 preflight。
3. 增加十条确定性合成图像、音频和文本 smoke 样本生成器。
4. 运行本地测试、安全扫描并提交到独立本地分支。

### B1：云环境释放后的无负载探针

1. 确认其他项目已结束。
2. 运行环境探针，记录 Python、PyTorch、torch-npu、Transformers、
   Accelerate 和 NPU 可见性。
3. 不安装依赖，不加载模型，不占用显存。
4. 如探针失败，只记录稳定阻断码并停止。

### B2：运行路线确认

按以下顺序选择一条经过实测的路线：

1. 比赛或 HiDevLab 官方提供的 A3 MiniCPM-o 4.5 方案；
2. 官方 Transformers 接口与当前 torch-npu 的最小兼容探针；
3. 官方明确支持当前设备时再考虑 FlagOS。

不得为了“能跑”而修改模型代码后继续声称使用官方 Base；任何兼容补丁
必须单独记录并与未修改的官方 revision 区分。

### B3：云端直接缓存模型

仅在 B1、B2 通过后执行：

1. 云端直接获取官方模型，不经过个人电脑；
2. 固定精确模型 revision；
3. 校验模型索引和权重分片存在；
4. 生成不含路径的 preflight 清单；
5. 切换为离线加载，后续运行禁止自动联网下载。

### B4：Base smoke 与冻结评测

1. 先加载文本、图像和音频模块，不启用 TTS 或全双工流式模式；
2. 对十条合成 smoke 样本运行推理；
3. 再对 Stage A 冻结测试集运行 Base；
4. 记录成功率、结构校验、拒答、引用、首字延迟、端到端延迟和峰值
   NPU 内存；
5. 保存模型 revision、代码提交、配置哈希、数据清单哈希和设备摘要。

### B5：LoRA 可行性门

只有 Base 可复现后才评估 BF16 LoRA。先验证十条合成样本的一次更新、
保存、重载和推理闭环。若 A3、显存或框架不兼容，停止扩大训练，
保留 Base 基线，不使用未经验证的量化训练替代结果。

当前本地分支已经准备好：

- 四路线 Base smoke 执行器；
- 五条冻结案例评测器；
- 十条 SWIFT 标准格式合成 LoRA 数据生成器；
- 单步 SWIFT LoRA 运行与适配器门禁；
- 适配器重载 smoke 和冻结复评入口；
- Base/LoRA 复合分数对比门。

这些代码通过本地假后端验证，不代表云端 MiniCPM-o 或 LoRA 已经运行成功。

## 验收

- 本地测试和安全扫描通过；
- 环境探针不泄漏路径、身份或设备序列号；
- 模型 revision 必须固定为精确提交；
- 模型缓存不完整时 preflight 失败关闭；
- Stage A 发布包存在发现项或来源泄漏时 preflight 失败关闭；
- smoke 生成物共十条，覆盖文本、图像和音频且字节确定；
- 云端运行前后均没有私有资料或本地模型传输。
