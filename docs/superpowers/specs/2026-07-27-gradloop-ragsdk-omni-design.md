# GradLoop RAGSDK Omni 设计规格

**正式标题：** GradLoop RAGSDK Omni<br>
**中文定位：** 证据约束的全模态学习与面试训练 Agent<br>
**副标题：** 面向课程学习、技术面试与科研答辩的“学—练—评—改”智能闭环<br>
**状态：** 已完成产品方向确认，等待书面规格复核后进入实施计划。

## 1. 目标与范围

GradLoop RAGSDK Omni 将用户拥有或公开授权的文字、文档、图像和音频材料转化为可检索、可追问、可评分、可复盘的训练过程。系统不以通用聊天为目标，而是要求每个事实性回答、追问和评分都能关联证据；证据不足时必须拒答或明确不确定性。

首个公开版本覆盖三个模式：

1. **课程学习**：概念讲解、知识测验、错因诊断和阶段复习。
2. **技术面试**：专业知识、代码理解、项目深挖、系统设计和压力追问。
3. **科研答辩**：研究动机、方法、图表、实验、创新点、局限性和质疑应对。

三个模式共用同一条能力链：

`材料理解 → RAGSDK 检索 → 自适应追问 → 多模态作答 → 双路评分 → 错题归纳 → 用户确认后调整计划`

## 2. 明确不做的内容

- 不将成绩、证明、证件、简历、论文私稿或其他个人材料用作训练数据。
- 不读取或上传本地私有知识库、飞书私有正文、本地索引或历史错题记录。
- 不抓取付费题库、登录后内容、商业面经、无许可证网页或仅可浏览的论文全文。
- 不把本地 Qwen 基线、模型权重、训练数据、检查点和实验输出提交到源码仓库。
- 不在首个版本实现账号、付费、多人协作、微信或飞书机器人。
- 不宣称 MiniCPM-o LoRA、RAGSDK 昇腾运行或实时全双工语音已经完成，除非对应实验产生可复现证据。

## 3. 仓库与系统边界

系统保持三层隔离：

### 3.1 主应用仓库

主应用负责 RAGSDK 适配、Agent 状态图、学习计划、批改、错题、前端和本地私有检索。它只通过稳定接口调用模型服务，不复制训练仓库实现。

### 3.2 训练仓库

本仓库只保存公开安全的源码、配置、测试和文档。真实数据放入被 Git 忽略的数据目录；模型权重、检查点、输出和传输包全部保持未跟踪。训练仓库产出的可公开内容仅包括配置模板、去标识的指标汇总、模型卡和数据卡。

### 3.3 昇腾开发环境

云端仅接收通过发布闸门的公开或合成数据包。MiniCPM-o 4.5 Base 直接下载到云端持久化目录，不经过个人电脑。云端不得接收本地私有语料、本地 Qwen 模型或任何用户材料。

两个本地仓库保持独立 Git 历史；本阶段不新增远端、不推送、不发布。

## 4. 组件设计

### 4.1 Source Registry

保存数据源声明和许可证决策，不直接保存正文。每个来源必须记录：

- `source_id`
- `canonical_url`
- `license_id`
- `license_url`
- `attribution`
- `commercial_use_allowed`
- `model_training_allowed`
- `redistribution_allowed`
- `modality`
- `retrieved_at`
- `content_sha256`

许可证采用默认拒绝策略：

| 许可证 | 公开训练 | 原始内容再分发 | 用途 |
| --- | --- | --- | --- |
| CC0-1.0 | 允许 | 允许 | 训练、评测、演示 |
| PDM-1.0 | 允许 | 允许 | 训练、评测、演示 |
| CC-BY-4.0 | 允许并署名 | 按许可证执行 | 训练、评测、演示 |
| CC-BY-SA-4.0 | 首版不进入公开权重 | 按相同方式共享 | 带引用检索或隔离研究 |
| CC-BY-NC 系列 | 禁止公开训练 | 禁止商业再利用 | 非商业人工参考 |
| ND、自定义、未知、仅 arXiv 分发许可 | 禁止 | 禁止 | 仅使用允许复用的元数据或事实 |

来源正文必须通过官方网站提供的 API、数据下载服务或明确允许的抓取方式获得。首批候选源为逐条许可筛选的 Open Textbook Library 教材、Python 等官方开放文档、PMC Open Access 商业可用子集、明确采用 CC0/CC-BY 的论文或媒体、Wikimedia Commons 单文件许可内容和 Common Voice CC0 语音。

### 4.2 Dataset Factory

数据工厂将许可通过的材料转化为统一训练记录：

```text
sample_id
scenario
task_type
modalities
evidence_ids
prompt
reference_answer
follow_ups
rubric
refusal_reason
provenance_ids
split
generation_method
quality_status
privacy_status
```

首批目标为 4,000 至 8,000 条高质量样本：

- 课程学习：30%
- 技术面试：30%
- 科研答辩：20%
- 图表、文档和语音理解：10%
- 拒答、安全、工具调用和证据不足：10%

同一个证据源不得跨训练、验证和测试集合出现近似段落。先按来源分组，再切分数据；切分完成后才能生成问题，避免问题改写造成数据泄漏。

### 4.3 Privacy and Release Gate

所有候选样本在进入云端前依次经过：

1. 许可证与来源完整性校验；
2. 个人信息、证件、联系方式和人脸风险扫描；
3. 凭证、访问密钥和本机绝对路径扫描；
4. 原文近似复刻和长连续片段扫描；
5. 重复样本和跨集合泄漏扫描；
6. 图像元数据、OCR 文本和音频转写扫描；
7. 固定比例人工抽检；
8. 生成只含通过记录的传输清单。

任何闸门失败都阻止整个包发布。通过条件为隐私阻断项、凭证阻断项、未知许可证和跨集合重复均为 0。

### 4.4 Multimodal Training Adapter

统一输入支持文字、文档页图、图表和音频。第一轮只训练任务行为和回答格式，不试图向模型注入大规模新知识：

- 根据给定证据回答并引用；
- 从材料生成逐层追问；
- 识别回答遗漏、矛盾和无证据扩展；
- 按结构化 rubric 输出评分；
- 证据不足时拒答；
- 输出可供 Agent 工具消费的严格结构。

MiniCPM-o 4.5 的训练顺序为：

1. 官方 Base 推理兼容性探针；
2. 公开小样本端到端 smoke test；
3. BF16 LoRA 小规模试验；
4. Base 与 LoRA 冻结集对照；
5. 通过质量和稳定性门槛后才扩大训练。

首选 LLaMA-Factory 作为 LoRA 编排层，ms-swift 作为兼容回退，OpenBMB 官方实现作为输入格式和推理行为的权威参考。若任一框架无法在目标 Ascend 环境通过 10 条全模态合成样本的训练与推理闭环，则不启动正式 LoRA，只保留 Base 推理和数据评测成果。

### 4.5 Agent Interface

训练模型不直接修改学习状态，只提供无副作用的能力：

- `answer_with_evidence`
- `generate_follow_up`
- `grade_response`
- `summarize_weakness`
- `interpret_multimodal_input`

主应用中的 Agent 才能调用检索、题库、计划、错题和确认工具。评分或计划调整失败时保留原状态；所有重规划必须先展示依据并等待用户确认。

## 5. 产品交互

公开 Demo 采用四个工作区：

1. **知识与证据库**：导入公开演示资料，显示许可证、索引状态和证据片段。
2. **课程学习**：围绕材料讲解、测验、追问和复习。
3. **技术面试 / 科研答辩**：选择场景和难度，以文字、图表或语音完成连续训练。
4. **成长与评测**：展示错题、能力维度、证据覆盖、模型对照和安全状态。

核心演示路径：

1. 导入一份开放许可讲义、一张实验图表和一段自制语音；
2. RAGSDK 建立证据索引；
3. 用户语音回答图表问题；
4. Agent 返回证据引用并连续追问；
5. 规则评分与模型复核共同给出反馈；
6. 错题和薄弱点写入演示用户状态；
7. 用户确认后更新学习计划；
8. 评测页展示检索、模型、延迟和安全结果。

## 6. 实验矩阵

| 编号 | 检索 | 生成模型 | Agent 闭环 | 运行位置 | 目的 |
| --- | --- | --- | --- | --- | --- |
| B0 | BM25 | 本地 Qwen | 否 | 仅本地 | 确定性基线 |
| E1 | RAGSDK | 规则或冻结生成器 | 否 | Ascend | 验证真实 RAGSDK 路径 |
| E2 | RAGSDK | MiniCPM-o Base | 否 | Ascend | 全模态 Base 基线 |
| E3 | RAGSDK | MiniCPM-o LoRA | 否 | Ascend | 衡量训练增益 |
| E4 | RAGSDK | 最优 MiniCPM 配置 | 是 | Ascend + 主应用 | 最终产品闭环 |

本地 Qwen 不上传到云端。所有横向比较使用同一冻结公开测试集、同一提示模板版本和同一指标实现。

## 7. 验收指标

### 7.1 安全与许可证

- 公开包中的隐私、凭证、本机路径和未知许可证阻断项均为 0。
- 训练集、验证集和测试集的来源级交叉数量为 0。
- 每个展示样本都能追溯到来源清单或合成配方。

### 7.2 检索与回答

- Citation Precision 不低于 0.90。
- Evidence Groundedness 不低于 0.85。
- 有答案问题的事实性幻觉率不高于 0.10。
- 无证据问题的正确拒答率不低于 0.85。
- RAGSDK 在困难子集的 Recall@5 不低于 BM25，并报告差值和置信区间。

### 7.3 训练与评分

- LoRA 相对 Base 的冻结集综合得分至少提升 5%，否则不将 LoRA 设为产品默认模型。
- 五分制人工评分与模型评分的平均绝对误差不高于 1.0。
- 评分输出结构校验通过率不低于 0.99。
- 三种场景分别报告结果，不用总体平均掩盖单一场景退化。

### 7.4 工程

- 每次实验记录代码提交、配置哈希、数据清单哈希、模型版本和设备信息。
- smoke test、单元测试、安全扫描和冻结评测均可由单一入口重复执行。
- Base 与 LoRA 分别记录首字延迟、端到端延迟、峰值 NPU 内存和失败恢复结果。

## 8. 错误处理

- 来源许可、robots、条款或网络目标不明确：拒绝采集并只输出稳定原因码。
- OCR、音频转写或解析失败：隔离单条样本，不让部分结果进入训练集。
- 模型输出不满足结构：最多重试一次；仍失败则使用确定性评分或返回不可评分。
- RAGSDK 后端不可用：明确返回 `backend_unavailable`，不得静默冒充 RAGSDK。
- LoRA 训练不稳定或 Ascend 不兼容：停止扩大训练，保留 Base 路线作为可交付基线。
- 任何安全扫描失败：阻断打包，不提供跳过参数。

## 9. 测试策略

- **单元测试**：许可证判定、来源规范化、数据结构、切分、去重、评分解析和错误原因码。
- **性质测试**：危险 URL、路径、编码、元数据和变形凭证均保持默认拒绝。
- **合成集成测试**：使用自包含的公开合成文字、图像和音频完成数据生产、训练格式转换和评测。
- **NPU smoke test**：10 条合成全模态样本完成加载、一次训练更新、保存、重载和推理。
- **冻结评测**：Base、LoRA、BM25、RAGSDK 与 Agent 使用同一公开测试集。
- **人工评测**：按课程学习、技术面试和科研答辩分层抽样，评分者看不到模型身份。
- **发布测试**：源码仓库、传输包和比赛材料分别执行隐私、凭证、路径、许可证和近似复刻扫描。

## 10. 分阶段交付

### 阶段 A：公开安全数据与评测底座

完成许可证策略、来源注册、数据 schema、来源级切分、隐私发布闸门、合成三场景样本和冻结评测入口。该阶段在本地即可独立验收。

### 阶段 B：Ascend Base 与 LoRA 实验

在 HiDevLab 完成 MiniCPM-o Base 探针、NPU smoke test、BF16 LoRA、小规模消融和可复现指标。只使用阶段 A 生成的公开安全传输包。

### 阶段 C：RAGSDK Agent 与比赛产品

通过稳定模型接口接入主应用，完成三种训练模式、证据引用、双路评分、错题与确认式重规划，并制作 Web Demo、视频、PPT、模型卡、数据卡和安全报告。

每个阶段单独编写实施计划、单独测试和单独复核；阶段 A 未通过发布闸门前，不进入阶段 B。

## 11. 最终决策

- 产品正式使用“GradLoop RAGSDK Omni——证据约束的全模态学习与面试训练 Agent”。
- 课程学习、技术面试和科研答辩共用一套证据约束训练框架，不拆成三个产品。
- 训练仓库与主应用仓库保持隔离；本地私有语料永不进入云端训练。
- 第一份实施计划只覆盖阶段 A；Ascend 训练和 Web Demo 分别在后续计划中实施。
- 所有公开能力声明必须由冻结评测、日志或可运行 Demo 支撑。
